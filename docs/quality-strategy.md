## 0. 一句话

这份文档回答一个问题：**我们的质量体系在证明什么，以及它还没在证明什么。**

结论先行：波 0 盘点时是 60 条条款、85 条判据、175 个通过用例 —— 它们证明的是「**PPT 是一份正确生产的数据结构**」；而「**PPT 是一份好 PPT**」这件事，在本项目里**至今没有被证明过**：波 1 补的三条规则（内容空 / 结论重复 / 版心稀疏）量的是**缺陷**，不是**好** —— 判据能说「这页太空」，说不出「这页讲清楚了没有」。波 0 已把这个断层从「不可见」变成「可见且有名字」，波 1 把「质量分凭什么这么算」从「实现说了算」变成「规则表说了算」，波 2 把「语义住在哪」「版式要什么」「字有多宽」问清楚；剩下的（人的判断、闸门阈值、悬空条款闭环）是波 3 的事。</</new_string>

## 1. 诊断：两条轴

### 1.1 轴 A —— 「是一份正确生产的数据结构」：验证密度很高

这一轴的问题形如「画布是不是 1920×1080」「ID 是否唯一」「SVG 是否转义」「导出是否保留文本」。它们都能被机器判定，判据写得出来、跑得起来、坏不掉。

| 指标 | 现状 |
|---|---|
| 条款数 | 68（technical 48 / business 12 / quality 5 / governance 3） |
| 判据数 | 101，**成熟度 100% `automated`** |
| 判据 oracle 构成 | `authoritative` 90 · `formal` 7 · `statistical` 2 · `expert` 2 · **`human` 0 · `self-derived` 0** |
| 单元 / 契约测试 | `bun test spec/verify/ packages/core/tests/ apps/api/tests/` → 330 通过 / 35 文件 |
| E2E 链 | 覆盖登录、建稿、编辑、放映、导出、离线、错误路径 |

> 波 0 盘点时是 60 / 85 / 175，上表是**本次回写时的现值**（68 / 101 / 330）。条款数会随并行开发变动，**指标口径不变** —— 下面每个数字都可以随时用脚本重数一遍。

这一轴可以继续加固，成本低、收益边际递减 —— 它已经不是瓶颈。

### 1.2 轴 B —— 「是一份好 PPT」：验证密度几乎为零

这一轴的问题形如「这页的核心结论有力吗」「这组卡片是不是在讲一件事」「这份 deck 拿去见客户行不行」。它们需要**外部判断**才能判定。

现状：

- **`human` oracle 数量为 0。** 全部 101 条判据的判据源，要么是文档（`authoritative`，90 条），要么是形式化约束（`formal`，7 条），要么是性能采样（`statistical`，2 条），要么是行业惯例（`expert`，2 条 —— 西文字宽表与四层分层各一条），要么曾经是**实现自己**（`self-derived`，波 1 已清零）。
- **`quality` 类条款仍只有 5 条**（占 7.4%）：`SPEC-QLT-011`（修复不得让文稿更糟）、`SPEC-QLT-012`（诊断须声明可否自动修复）、`SPEC-NFR-001/002/003`（性能与降级），其中**没有一条**在评价「内容好不好」。波 1 新增的三条内容规则（`SPEC-QLT-015/016/017`：内容空 / 结论重复 / 版心稀疏）按 `technical` 归类 —— 它们的判据是「规则表与文档逐行对齐」这种可机械核对的契约，**量的却是内容质量**。轴 B 的第一批判据已经出现，但它们证明的是**缺陷**，不是**好**。
- **`semi` / `manual` 成熟度的条款与判据：0 条。** 整个可执行规格里没有任何一个环节是「人要来看一眼才算过」。
- **8 条 `known_gaps`** 全部指向「已知没做到」，而不是「做到了但没被证明」—— 这说明缺的不是结论，是**结论本身**。

### 1.3 断层的三种具体症状

断层不是抽象的，它以三个可指认的 bug 出现过 —— 波 0 就是把它们修掉：

| 症状 | 表现 | 波 0 处置 |
|---|---|---|
| **自证** | 7 条判据的 oracle 源是 `packages/core/src/engine/qualityEngine.ts` 自己 —— 实现扣 15 分，判据说「扣 15 分是对的」 | 波 0 记为 `self-derived` 并公开计数；波 1 逐条追认 → **清零** |
| **语义外露在字符串里** | 渲染分层靠 ID 前缀 `header_` 决定 kicker 走哪个层；前端主题重映射靠 `header_` / `accent` 决定配色；「一键修复」把 ID 洗成元素类型 —— **元素直接掉出模板层，换模板时不再跟随 accent 色** | 波 0 保住前缀；波 2 ① 语义搬到显式字段 `SlideElement.variant`（ADR-018）✅ |
| **承诺大于实现** | 每条诊断都写着「重命名为唯一 ID」「网格自动对齐重排」，但网格重排根本没实现 —— 用户点「一键修复」，什么都没发生，还被告知「已修复」；侧边栏写死的 `?? 92` 分是一个从没体检过的文稿的体检结果 | 波 0 引入 `fixable` 声明 + 分数如实显示 |

> 三个症状同源：**产品的承诺跑在实现前面，而规格体系只会验证「实现做了什么」，不会验证「承诺说到做到没有」。** 所以波 0 的重点不是修 bug，是给「承诺 vs 实现」这一层加上可执行的判据（`SPEC-QLT-009` ~ `SPEC-QLT-012`、`SPEC-RND-006`）。

## 2. 四个波次

### 波 0 · 止血（✅ 已完成，提交 `4ef42a3`）

**目标：让「一键修复」不再毁文稿，让界面不再说假话。**

| 动作 | 落点 |
|---|---|
| 越界判据从「内容安全区」改成「画布边界」；没越界的元素一个坐标都不许动 | `packages/core/src/engine/qualityEngine.ts` · ADR-014 |
| ID 重排保留语义前缀（`header_s1` → `header_s1_1`，不是 `text_s1_1`） | 同上 · `SPEC-QLT-010` |
| 修复后复评，任一维度不得低于修复前；修坏了整体退回 | 同上 · `SPEC-QLT-011` |
| 每条诊断显式声明 `fixable`；不可修项的按钮置灰并说明原因 | `QualityIssue.fixable` · `src/components/QualityCenter.tsx` · `SPEC-QLT-012` |
| 侧边栏不写死 92 分，拿不到报告就不显示徽章 | `src/App.tsx` · `src/components/SidebarNav.tsx` |
| 截断判据从「看行数」改成「看内容」——`lines.length === 1 && lines[0] === block.text` | `packages/core/src/engine/svgRenderer.ts` · `SPEC-RND-006` |

**留下的债（明确不在波 0 解决）**：语义仍外露在 ID 里（→ 波 2 ✅ 已落地，ADR-018）；7 条判据仍是自证（→ 波 1 ✅ 已清零）；`AMB-001` 阈值仍未裁决（→ 波 3，未动）。

### 波 1 · 引擎（把评分从「实现即真相」变成「规则表驱动」）✅ 已完成

**目标：质量分是规则的输出，不是实现的输出。**

1. **把 `qualityEngine` 的 8 条规则抽成一张规则表**（`id` / 维度 / 判据 / 扣分 / `fixable` / 依据出处），规则表是**数据**，评分器退化为解释器。规则表本身是一份可被 spec 引用的文档（`docs/quality-rules.md`）。
   - 落点：`packages/core/src/engine/qualityRules.ts`（机器副本）+ [`quality-rules.md`](./quality-rules.md)（真相源）+ `spec/verify/quality-rules.test.ts`（逐行比对，两者漂移即失败）+ ADR-015。
   - 引擎里不再出现任何 `+= 15` —— 幅度全部查表。
2. **7 条 `self-derived` 判据逐条追认或删除**：能追认的（实现与文档一致）把依据补成文档引用、升为 `authoritative`；追认不了的（文档没写过这个幅度）**改文档**，而不是改判据去迁就实现。
   - 落点：6 条质量判据 + `AC-RND-005` 全部升为 `authoritative` → **M1 = 101/101 = 100%**（基线 91.8%）。⚠️ 波 1 落地时其实只到 **94/95** —— `AC-RND-005` 的外部依据（`docs/test-cases.md §TC-CORE-146`）直到本次文档回写才补齐；**M1 当时差一条没到 100%**，是这张表自己把它查出来的。
3. **裁决歧义**：`AMB-002`（越界按画布还是安全区 —— 波 0 已经事实上选了画布，需回写文档）、`AMB-004`（10px 是容差还是安全距）、`AMB-003`（字体 fallback 链顺序）。裁决只做一次，规则表全局生效。
   - `AMB-002` → **画布边界**用于扣分、安全区用于版式约束（DEC-002，ADR-014/015 回写）。
   - `AMB-003` → **SVG 侧 CSS 字体栈（主题拉丁字体 → 显式 CJK 族 → generic）、PPTX 侧单名 `'Microsoft YaHei'`**（DEC-013，ADR-016）。
   - `AMB-004` → **10px 是安全距，不是容差**（DEC-014，ADR-017）。判据补了分水岭用例：重叠 5px → 判碰撞；间隙 5px → 判碰撞；间隙恰好 10px → 判不碰撞。
   - 裁决的代码落地：`packages/core/src/engine/typography.ts`（`withCjkFallback` / `PPTX_FONT_NAME`）+ `qualityEngine.ts` 的 `separation()`；回归锁 `spec/verify/font-fallback.test.ts` 与 `spec/verify/quality-engine.test.ts`。
4. **补两条至今没有的规则族**，它们正是「数据正确」与「PPT 好」的交界：
   - **跨页论点重复**（`Qc`，`content_dup`，−10）：同一个结论在三页里各说一遍，是内容分现在完全看不见的缺陷。归一化后比较（去空白、去标点、小写），封面不参与。
   - **留白与密度**（`Qv`，`vis_sparse`，−8）：承载信息的内容盖不满版心。阈值 **20%** 来自实测（真实版式 30.8%–82.2%，只有标题的页面 9.5%），密度用**矩形并集**（包围盒高估到 53.6%、面积之和高估到 137.9%）。
   - 规则总数 8 → **11**。

**波 1 的两个副产品**（计划外但由裁决必然引出）：

- **零缺陷夹具必须真的长得像一页 PPT**。`spec/verify/helpers.ts` 的 `makeCleanSlide` 原来只有标题 —— 它触发 `content_thin` 与 `vis_sparse`，基线本身是脏的。改成按真实版式的几何构造（有卡片、每页结论互不相同、版心占用率 38.3%）。
- **质量报告的数字必须能对账**。11 条规则的扣分幅度全部有文档出处，判据逐条引用 —— 这是 M1 达标的前提。

### 波 2 · 版式（把语义从字符串里搬走）

**目标：元素的身份不再由它的 ID 决定。**

1. ✅ **已完成 · 执行 ADR-018 的 `SlideElement.variant`**：`SlideElement` 增加显式的 `variant` 字段（顶层、带类型），变体的全部语义收进一张表 `ELEMENT_VARIANTS`（层归属 / 是否跟随 accent 色 / ID 语义前缀）。渲染分层、主题重映射、ID 生成一律改读字段，不再解析 ID 字符串。这条债是波 0 挖出来的根因 —— 只要语义还住在 ID 里，任何一次「重命名」都是一次事故。
   - **三处语义外露点全部归零**（M3 达标）：`svgRenderer` 分层、前端主题重映射、质量引擎 ID 重排。
   - **顺带修掉一个真 bug**：主题重映射曾有三份抄写，其中 App 那份给 divider 写的是 `style.color`，而分隔线画的是 `style.backgroundColor` —— **换主题后强调线不换色**。三份合并成 `themeRemap.ts` 一份。
   - **旧数据靠唯一兼容层迁移**：`legacyVariantOf()` 只在 `variant` 缺失时触发，读入时 `withVariants()` 幂等补齐（服务端三处 + 前端一处）。
   - **判据**：SPEC-CORE-010 的四条（AC-CORE-014 ~ AC-CORE-017），其中 AC-CORE-017 做**源码级扫描** —— 全仓生产代码零处解析元素 ID。
2. ✅ **已完成 · 64 组快照回归升级**：8 版式 × 8 主题，从「渲染不崩、不断言别的」升级为「断言不变量」—— 层归属正确、accent 色正确跟随、无越界、无截断、无碰撞。这是波 1 规则表在版式侧的对应物。
   - **落点**：`packages/core/tests/layoutInvariants.test.ts`（SPEC-GOV-004 的五条判据）。不变量在**渲染产物**上判定，不在 IR 上自我复读 —— 「层归属正确」查的是 SVG 里元素落在哪一层 `<g>`，「无截断」查的是 SVG 的文本节点里有没有那段原文。
   - **顺带查出一处真 bug**：64 组里 `stats_kpi` 的 8 组**从来没被真正测过** —— 夹具要点里没有数字，`resolveLayout` 把每一页都降级成了 `cards_grid`，于是「8 版式 × 8 主题」里有一个版式测的全是另一个版式。夹具改成给指标页配带数字的要点后，那 8 组快照重建，64 组才真的是 64 组。
   - **判据**：SPEC-GOV-004 的两条（AC-GOV-003 五条不变量、AC-GOV-004 质量引擎对 64 组零命中）。
3. ✅ **已完成 · 版式意图显式化**：`packages/core/src/data/layoutIntents.ts` 的 `LAYOUT_SLOT_CONTRACTS` 把「版式 → 需要哪些内容槽位」写成表（`consumes` / `fallbackFrom` / `requires` / `produces` / `requiresVariants` / `degradesTo`），`contentBinding` 从「绑定器」升级为「校验器」（`validateContentForLayout` 给出结论，不再硬塞）。详见 ADR-020。
4. ✅ **已完成 · 文本度量统一**：旧的宽度口径是「全角 1em / 半角 0.56em」—— 一个数字管所有半角字符，`WWWW` 少估 40%（横向溢出）、`iiii` 多估 2.5 倍（白折一行）。ADR-019 改成两路：全角按 1em，半角查标准西文 advance width 表 × 1.08 安全系数；折行顺带补上一个洞（空格断行时尾段超宽 → 退化为硬断），保证「每一行的估算宽度都 ≤ 可用宽度」。
   - **判据**：SPEC-RND-007 的两条（AC-RND-007 / AC-RND-008）—— 参照值取自公开的 Helvetica 字形宽度，**不是抄实现**；实现里的表若与它对不上，判据立刻挂。

### 波 3 · 体系（把「好」变成可验收）

**目标：让「这是一份好 PPT」这句话有判据、有人、有闸门。**

1. **质量闸门落地**：裁决 `AMB-001`（AI 生成内容落库前的 Q 阈值），把数字写进 `backend-features.md` 与 `spec.yaml`，`SPEC-GOV-003` 从 `status: blocked` / `maturity: none` 变成有判据的 active 条款。
2. **引入 `human` / `expert` oracle**：结构化人评 checklist（每份文稿约 15 分钟，评价 Qs/Qv/Qc/Qg 四维 + 整体可用性），产出 `M4` 的基线。**这是整个战略里唯一必须引入新成本的一步**，也是价值密度最高的一步 —— 没有它，「好 PPT」在本项目里永远只是一个形容词。
3. **`known_gaps` 闭环**：现有 8 条每条要么补判据、要么把条款降级为 `withdrawn` / `blocked` 并写明原因，不留「已知没做到但状态仍是 active」的悬空条款。
4. **追溯矩阵成为发布闸门**：`spec/traceability.md` 的结论列从「记录」变成「拦截」—— 有 INCOMPLETE 的高风险条款就不发版。

## 3. 五个指标

每个指标都有**当前基线**和**目标值**，且都能从仓库里机械地数出来 —— 没有「感觉变好了」这种指标。

| # | 指标 | 定义 | 当前基线 | 目标 |
|---|---|---|---|---|
| **M1** | **判据外部化率** | 非 `self-derived` oracle 的判据 ÷ 全部判据 | ~~78 / 85 = 91.8%~~ → **101 / 101 = 100%** ✅ | **100%**（7 条自证要么补外部依据，要么删） |
| **M2** | **自动修复覆盖率** | `fixable: true` 的规则族 ÷ 全部规则族 | ~~3 / 8 = 37.5%~~ → **3 / 11 = 27.3%**（`struct_dim` / `struct_id` / `vis_bounds`）⚠️ 目标已修正，见下 | **修正为**：机械可修的缺陷**必须**全部声明为可自动修复（现值 **3 / 3 = 100%**），且每条不可修项给出**人工可执行**的具体步骤 |
| **M3** | **语义外露点** | 靠解析 ID 字符串决定渲染/配色/修复行为的位置数 | ~~**3**（svgRenderer 分层、前端主题重映射、质量引擎 ID 重排）~~ → **0** ✅（波 2 ① 落地：`SlideElement.variant` 接管全部三处，AC-CORE-017 源码级扫描钉死） | **0**（恒为 0；新增解析 ID 的消费方一律不予合入） |
| **M4** | **质量分与人工评价的一致性** | 自动四维分与人评四维分的 Spearman ρ，样本 ≥ 20 份 | **无基线**（`human` oracle = 0 条） | ρ ≥ **0.6**（波 3 的人评 checklist 产出首个基线） |
| **M5** | **未兑现承诺数** | 界面上声称能做、实际没做的修复动作条数 | **0**（波 0 前：7 条修复文案里有 4 条无对应实现） | 恒为 **0**；新增规则必须先声明 `fixable`，否则不予合入 |

> M1、M3、M5 可用脚本直接从 `spec/spec.yaml` 与源码里数；M2 需要读 `qualityEngine` 的规则表；M4 需要人评基础设施（波 3）。

#### M2 的目标修正记录（⚠️ 不是把指标改小，是把目标改成能兑现的）

原目标是「≥ 60%」。波 1 落地后这个数**不可达**，原因不是实现偷懒，而是**分母的性质变了**：

- 波 1 补了 3 条规则（`content_thin` / `content_dup` / `vis_sparse`），它们**按构造就不能自动修** —— 「这一页太空」「这几页在说同一句话」「这页没有核心结论」，修它们都要**替用户写内容**，而本战略 §6 明确写着「那是替用户定业务规则，违反『不编造业务规则』」。
- 于是比值从 3/8 掉到 3/11 —— **分母长的是「诚实地声明不可修」的规则，比值因此被稀释**。一个只留 3 条规则、且都标成可修的实现，M2 是 100%，而它什么缺陷都查不出来。**这个比值奖的是删规则，不是修缺陷。**
- 所以目标改为**可证伪的不变式**：「机械可修的缺陷（画布尺寸、ID 唯一、几何越界）**必须**全部声明为可自动修复」—— 现值 3/3 = 100%。若将来有人把 `vis_bounds` 标成不可修，M2 立刻掉到 2/3，这条不变式就会报警。
- 原目标的**第二半**（「每条不可修项给出人工可执行的具体步骤，不留『建议人工调整』这种空话」）**保留且已达成** —— 那是 ADR-014 兑现过的部分。
- 比值本身仍然公开报告（3/11 = 27.3%），不藏。

## 4. 三个待裁决的决定

这三件事**不是工程问题，是产品与内容的决定**，工程侧无法代答。它们卡住了波 1 的一处与波 3 的全部。

### D1 · 质量分的阈值定多少、由谁定？

`AMB-001` 至今未裁决：文档只写「Q ≥ 阈值 → 落库；Q < 阈值 → 降级 / 重生成 / 拒绝」，**从未给出这个数字**。`SPEC-GOV-003` 因此挂着 `status: blocked` / `maturity: none`、零条判据 —— 闸门是敞开的。

- 需要谁定：内容 / 设计负责人（质量分是「对受众好」还是「对系统好」，只有人知道）。
- 需要定什么：一个数字（或分档：AI 生成内容落库线、人工复核线、发布线）。
- 不定会怎样：质量分永远只是给人看的数字，**没有任何地方依赖它** —— 闸门形同虚设。
- 顺带要修：`SPEC-GOV-003` 的 `statement` 现在写的是「待 **AMB-002** 裁决阈值后填写」，但阈值这条歧义编号是 **AMB-001**（`AMB-002` 是越界判据那条）。裁决时顺手改对，别让两个编号各说各话。

### D2 · 三条歧义谁来裁决？ ✅ 已裁决（波 1）

`AMB-002`（越界按画布还是安全区）、`AMB-003`（字体 fallback 链）、`AMB-004`（10px 缓冲是容差还是安全距）—— 每一条都会改变质量分的具体数值。

| 歧义 | 裁决 | 落点 |
|---|---|---|
| `AMB-002` 越界按画布还是安全区 | **画布边界**用于质量扣分，**安全区**用于版式生成的布局约束 —— 两者并存，不矛盾 | DEC-002 · ADR-014 · ADR-015 · `docs/backend-features.md §I QLT-02` |
| `AMB-003` 字体 fallback 链 | **SVG 侧 CSS 字体栈**（主题拉丁字体 → 显式 CJK 族 → generic，CJK 族必须在 generic 之前）；**PPTX 侧单名** `'Microsoft YaHei'`（DrawingML 没有链） | DEC-013 · ADR-016 · `packages/core/src/engine/typography.ts` · SPEC-EXP-006 |
| `AMB-004` 10px 是容差还是安全距 | **安全距**。间距 = `max(dx, dy)`，不足 10px 即判碰撞，恰好 10px 判不碰撞 | DEC-014 · ADR-017 · `docs/quality-rules.md §vis_collide` |

裁决只做一次，规则表全局生效。三条都在 spec 里从 `status: OPEN` 改为 `RESOLVED`，并各自留了一条 `proposed_default` 写明结论与理由 —— 半年后再有人问「为什么是安全距不是容差」，答案是**在文档里**，不是「记得吗」。


### D3 · 要不要引入人工评审环节？

`human` / `expert` oracle = 0，是本战略最大的缺口，也是唯一需要**新增成本**的一步。

| 选项 | 代价 | 收益 |
|---|---|---|
| **A. 不做**，只把自动化质量分做到极致 | 0 | M1–M3、M5 达标；但「好 PPT」永远无锚点，产品无法回答「这次改动是不是让 PPT 更好了」 |
| **B. 轻量人评**（每份 15 分钟 checklist，抽样而非全量） | 每人每份 15 分钟；需要一名内容负责人 | M4 有基线；波 3 的闸门有阈值依据；缺陷逃逸能被看见 |
| **C. 全量人评** | 与开发同量级人力 | 统计显著；**当前阶段不划算** —— 规则表都还没有，先量化噪声再谈全量 |

建议 **B**：先建基线，规则表稳定后再考虑是否升级到 C。

## 5. 波次依赖与顺序

```
波 0 止血 ✅ ──▶ 波 1 引擎 ✅ ──▶ 波 2 版式 ✅ ──▶ 波 3 体系
                    │            │            │
                    ├─ D2 裁决 ✅├─ 64 组快照  ├─ D1 阈值
                    └─ M1 ✅/M2  └─ M3 ✅      ├─ D3 人评
                                    ① 语义搬迁 ✅└─ M4 / M5
                                    ③ 槽位契约 ✅
                                    ④ 文本度量 ✅
                                    ② 快照断言 ✅
```

- **波 1 与波 2 可以并行**：一个动评分器，一个动版式引擎，二者唯一的交集是「语义前缀由谁负责」（波 1 写规则表时按波 0 的口径「前缀不被洗掉」，波 2 把前缀彻底换成字段）。
- **波 3 依赖波 1**：规则表不稳定时，人评 checklist 评什么都会漂。
- **每一波都必须同时落 spec 条款与判据** —— 波 0 的四条新判据（`SPEC-QLT-009` ~ `012`）与 `SPEC-RND-006` 就是这个规矩的样板：**没有判据的改进等于没改进**。

## 6. 明确不做的事

- **不做「AI 打分」**：质量分必须由确定性规则算出，否则它既不可复现也不可当闸门用。AI 只负责生成内容，不负责评价内容。
- **不把 `self-derived` 判据当成荣耀**：自证判据不是「通过率高」，是「这条结论目前没有外部依据」。M1 的目标是把它们清空，不是把总数做大。
- **不追求 100 分**：质量分是**分档工具**，不是竞赛分数。为了拉高 Q 而加规则、只为让分数好看，是把工具变成 KPI。
- **不把波 2 的语义搬迁塞进波 1**：64 组快照重建是一次独立的、有明确验收面的工程（由 `SPEC-RND` 与版式条款覆盖），混进来会让两件事都做不好。
