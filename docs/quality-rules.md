# 质量规则表 —— 扣分幅度的权威依据

> **这份文档是「一次质量缺陷扣多少分」的唯一真相源。**
>
> 实现侧的对应物是 [`packages/core/src/engine/qualityRules.ts`](../packages/core/src/engine/qualityRules.ts)
> 里的 `QUALITY_RULES`。两边必须逐行对齐 —— 对齐由
> `spec/verify/quality-rules.test.ts` 强制执行（表多一行、文档少一节，或扣分
> 幅度对不上，测试就红）。

---

## 1. 为什么需要这张表

以前扣分幅度直接写死在 `qualityEngine.ts` 里：

```ts
totalStructurePenalties += 15;   // ← 「15」的唯一依据就是「代码里写的是 15」
```

于是每一条判据只能**自证**（oracle tier = `self-derived`）：验收用例断言
「结构分等于 85」，而「85」是怎么来的？——「因为代码里扣 15」。文档与实现
谁对谁错没人说得清，改一个数字也不会有人发现。

现在规则表是**数据**，评分器退化成它的解释器：

| 以前 | 现在 |
|---|---|
| 扣分幅度写在引擎里 | 扣分幅度写在这份文档里，引擎从表里读 |
| 判据自证（`self-derived`） | 判据引用本文档（`authoritative`） |
| 改幅度 = 改代码 = 没人发现 | 改幅度 = 改文档 ≠ 改表 = 测试红 |

规则 `id` 同时是**诊断 id 的前缀**（`struct_dim_${slideId}`、`vis_bounds_${el.id}`…），
保证「诊断」与「规则」一一对应：界面上看到的每一条问题，都能顺着 id 找到
本文档里对应的那一节。

## 2. 规则总表

> 维度一列用英文 token（`structure` / `visual` / `content` / `consistency`），
> 与 `QualityReport` 的字段名一致，避免中英对照表带来的歧义。

| 规则 id | 维度 | 扣分 | 可自动修复 | 判据 |
|---|---|---|---|---|
| `struct_dim` | `structure` | 15 | 是 | 画布尺寸必须是 1920×1080 |
| `struct_id` | `structure` | 5 | 是 | 元素 ID 全局唯一 |
| `vis_bounds` | `visual` | 10 | 是 | 元素不得越出画布边界 |
| `vis_collide` | `visual` | 8 | 否 | 卡片 / 层之间不得 AABB 碰撞（10px 安全距） |
| `vis_sparse` | `visual` | 8 | 否 | 承载信息的内容不得只盖住内容安全区面积的 20% 以下 |
| `content_title` | `content` | 15 | 否 | 每页必须有明确的标题概括（≥ 3 字符） |
| `content_keymsg` | `content` | 8 | 否 | 非封面页必须有一句话核心结论 |
| `content_thin` | `content` | 8 | 否 | 非封面页必须至少有一个实质内容件（卡片 / 层 / 指标 …） |
| `content_dup` | `content` | 10 | 否 | 不同页的核心结论不得重复 |
| `consist_count` | `consistency` | 15 | 否 | 整份文稿至少 3 页 |
| `consist_cover` | `consistency` | 10 | 否 | 整份文稿必须有一页封面 |

**11 条规则**，覆盖四个维度。总分计算：

```
Q = 0.3·Qs + 0.3·Qv + 0.2·Qc + 0.2·Qg
```

每个维度从 100 分起扣，钳制在 0–100；`overallScore` 取整。

## 3. 逐条说明

<a id="struct_dim"></a>
### `struct_dim` · 画布尺寸必须是 1920×1080

- **判据**：任一页的 `canvas` 不等于 `{width: 1920, height: 1080}` 即违例，每页各扣一次。
- **扣分 15 的理由**：画布比例不对会让这一页的所有版式坐标失去意义 —— 导出、
  预览、PPTX 三个出口全部错位。它不是「不好看」，是「这一页根本不是这样
  渲染的」，属于结构性问题，比内容问题严重。
- **边界**：`x+width` 之类的越界判定不归本条，归 `vis_bounds`。
- **可自动修复**：是。修复即把 `canvas` 重置为 1920×1080 —— 无歧义、无损。

<a id="struct_id"></a>
### `struct_id` · 元素 ID 全局唯一

- **判据**：同一个元素 ID 在整份文稿里出现第二次即违例，每重复一次扣一次。
- **扣分 5 的理由**：重复 ID 会让「选中这个元素」指向不确定的对象 —— 编辑、
  删除、局部重渲染都可能落到错误的元素上。但它不会让文稿**看起来**坏，所以
  扣得比 `struct_dim` 轻。
- **边界**：跨页重复同样算（ID 是全局命名空间）。
- **可自动修复**：是。修复重排 ID，**保留语义前缀**（见
  [`architecture.md` §12 ADR-014](./architecture.md)）。

<a id="vis_bounds"></a>
### `vis_bounds` · 元素不得越出画布边界

- **判据**：任一 `role ≠ background` 的元素满足 `x < 0` 或 `y < 0` 或
  `x + width > 1920` 或 `y + height > 1080` 即违例。
- **扣分 10 的理由**：越界的元素有一部分在画布外 —— 观众**看不到**它。
  内容看不见就等于不存在，这是硬伤。
- **边界**：
  - 恰好 `x + width === 1920` 或 `y + height === 1080` **不算越界**（贴着边是合法的）；
  - `role = background` 豁免（铺满画布是设计如此）；
  - 越界判据取**画布边界**，不是内容安全区 —— 母版页码与页脚本来就贴着画布
    下沿，它们在画布内、只是不在内容安全区内（见 ADR-014）。
- **可自动修复**：是。修复把越界元素平移回内容安全区，**优先保持原尺寸**。

<a id="vis_collide"></a>
### `vis_collide` · 卡片 / 层之间不得 AABB 碰撞（10px 安全距）

- **判据**：两个 `role ∈ {card, layer}` 的元素，其轴对齐包围盒之间的**间距不足
  10px** 即违例，每一对扣一次。间距的定义是
  `separation(a, b) = max(dx, dy)`，其中
  `dx = max(b.x − (a.x+a.width), a.x − (b.x+b.width))`、`dy` 同理 ——
  **负值表示重叠，0 表示相接，正值表示间隙**。
- **扣分 8 的理由**：文字压在文字上，两块内容互相不可读。它比越界轻（内容还在），
  比「留白过多」重（内容真的糊了）。
- **边界**：
  - **10px 是安全距，不是容差**（AMB-004 裁决，见 `spec.yaml` 的 DEC-014）：
    两块之间必须留出 10px 才算「分开的」，否则判碰撞。**恰好 10px 判不碰撞**。
    取安全距而不是容差，是因为容差读法会把间距 5px 的两张卡放过 —— 而 5px
    间距的卡片在视觉上是糊成一块的，那正是这条规则要抓的缺陷；
  - 只查 card / layer 两类，标题、图标、连接线不参与 —— 它们与卡片重叠是版式
    的常规手法。
- **可自动修复**：**否**。自动重排要重排整页内容并重新分配栅格，那是一次
  版式重生成，不是「修复」。界面上给的是**人工可执行的具体步骤**（拉开哪两个
  元素、拉到多少），不是「建议人工调整」。

<a id="vis_sparse"></a>
### `vis_sparse` · 承载信息的内容不得只盖住内容安全区面积的 20% 以下

- **判据**：一页里**承载信息**的元素（`role ∈ {title, subtitle, card, layer, metric,
  badge, connector, chart, icon, annotation}`）的**矩形并集**与内容安全区
  （左 100 / 上 60 / 右 1820 / 下 1020，面积 1720×960）求交后，面积占比 < 20% 即违例。
- **扣分 8 的理由**：大片留白本身不违法，但一页 PPT 看起来像「没排完」——
  这正是自动生成的稿子最常见的观感缺陷。
- **为什么用矩形并集**：两种偷懒的算法都会算错：
  - **面积之和**会把同一块版面数好几遍 —— 卡片里套着标题与正文时，
    `architecture_diagram` 的面积之和是安全区的 **137.9%**；
  - **包围盒**会把「标题在上、卡片在下」这种上下分离的版面算成一大块 ——
    `title_cover` 的包围盒是 **53.6%**，而它实际只铺了 **30.8%**。
  矩形并集（坐标压缩 + 逐格判定）才是「这一页真正被内容盖住了多少」。
- **20% 这个数怎么来的**：**实测标定**，不是拍的 ——
  | 场景 | 覆盖率 |
  |---|---|
  | 真实版式最低（`title_cover`） | 30.8% |
  | 真实版式最高（`architecture_diagram`） | 82.2% |
  | 「只有标题」的页面 | 9.5% |
  | **本规则阈值** | **20%** |
  20% 落在 9.5% 与 30.8% 中间 —— 真实版式一条都不误报，稀疏页面一条都不漏网。
- **边界**：
  - 与 `content_thin` **互斥**：一页已经因「没有实质内容件」扣过分，就不再因
    「因此显得稀疏」重复扣一次；
  - 封面不豁免本条（真实封面实测 30.8%，正常封面不会被判稀疏），但封面豁免
    `content_thin`。
- **可自动修复**：**否**。把内容撑满版面需要重新排版；给的是人工步骤。

<a id="content_title"></a>
### `content_title` · 每页必须有明确的标题概括（≥ 3 字符）

- **判据**：任一页的 `title` 为空或少于 3 个字符即违例，每页扣一次。
- **扣分 15 的理由**：标题是这一页的**论点**。没有标题的页在汇报时观众不知道
  这一页要讲什么 —— 这是内容维里最重的缺陷（与 `struct_dim` 同档）。
- **边界**：封面也受检（封面没标题本身就是错的）；长度恰好 3 通过，2 扣分。
- **可自动修复**：**否**。写标题要人（或模型）来写，自动生成等于编造。

<a id="content_keymsg"></a>
### `content_keymsg` · 非封面页必须有一句话核心结论

- **判据**：非封面页（`layout.type ≠ title_cover`）的 `keyMessage` 为空即违例。
- **扣分 8 的理由**：核心结论是「这一页要观众记住的那一句」。缺了它，页面能看
  但讲不出结论。扣得比标题轻，因为它是「缺失」而非「错误」。
- **边界**：封面豁免（封面通常就是标题页，没有 takeaway 是正常的）。
- **可自动修复**：**否**。同上，写内容要人来写。

<a id="content_thin"></a>
### `content_thin` · 非封面页必须至少有一个实质内容件

- **判据**：非封面页里 `role ∈ {card, layer, metric, badge, chart}` 的元素个数
  为 0 即违例。标题、副标题、连接线、图标**不算**实质内容件 —— 一页只有
  「标题 + 一句话结论 + 一个图标」时，它没有承载任何可汇报的信息。
- **扣分 8 的理由**：空话页（「感谢聆听」「综上所述」）撑不起一次汇报。
- **边界**：封面豁免（封面本就不该有卡片）；与 `vis_sparse` 互斥（见上）。
- **可自动修复**：**否**。补内容是创作，不是修复。

<a id="content_dup"></a>
### `content_dup` · 不同页的核心结论不得重复

- **判据**：把每页的 `keyMessage` 归一化（去空白、去标点、转小写）后分组，
  同一组里第 2..n 页各扣一次。归一化是为了让「我们把质量分提高了 10%。」与
  「我们把质量分提高了10%」被认出来是同一句话。
- **扣分 10 的理由**：同一个结论在三页里各说一遍 —— 观众听完只记住了一件，
  而汇报的推进感来自每页都有新东西。这是**内容重复**，比「少一句结论」严重。
- **边界**：
  - 封面不参与（封面的 keyMessage 常常是空的）；
  - 空结论不参与（已由 `content_keymsg` 判，不重复扣分）；
  - 一组 n 页扣 (n−1) 次 —— 第一页是「原版」，后面才是重复。
- **可自动修复**：**否**。合并重复结论要判断「这两页是不是该合成一页」——
  这是编辑判断。

<a id="consist_count"></a>
### `consist_count` · 整份文稿至少 3 页

- **判据**：整份文稿页数 < 3 即违例，整份扣一次。
- **扣分 15 的理由**：少于 3 页撑不起一次完整汇报（封面 + 至少一页内容 + 收尾）。
- **边界**：恰好 3 页通过。
- **可自动修复**：**否**。凭空生成页面是创作。

<a id="consist_cover"></a>
### `consist_cover` · 整份文稿必须有一页封面

- **判据**：整份文稿里没有 `layout.type === title_cover` 的页即违例，整份扣一次。
- **扣分 10 的理由**：没有封面，观众一上来不知道这是关于什么的。缺封面比
  页数少 2 页轻 —— 它是「不完整」，不是「讲不清」。
- **边界**：封面可以不在第一页（引擎不强制页序），但必须存在。
- **可自动修复**：**否**。插一页封面要决定标题、副标题、信息卡的内容。

## 4. 「可自动修复」是什么意思

`fixable: true` 的**唯一**含义是：「一键修复」这个按钮真的会把它修掉」。
只有真做了自动修复的规则才为 `true` —— 这是
[`architecture.md` §12 ADR-014](./architecture.md) 的决策。

| 规则 | 一键修复做什么 |
|---|---|
| `struct_dim` | `canvas` 重置为 1920×1080 |
| `struct_id` | 重排元素 ID（保留语义前缀，保证全局唯一） |
| `vis_bounds` | 把越界元素平移回内容安全区（保持原尺寸优先） |

其余 8 条 `fixable: false`。它们在界面上给出的是**人工可执行的具体步骤**
（「把这两个卡片拉开 10px 以上」），而不是「建议人工调整」这种空话 ——
一条不可自动修的诊断，至少要让人知道**具体该做什么**。

修复本身还要满足一条硬约束（SPEC-QLT-011）：**修复后复评，任一维度分数
不得低于修复前** —— 修坏了就整体退回，宁可不修也不能修坏。

## 5. 这张表**故意不**管的事

- **好看不好看**：配色、字体搭配、留白的美学判断 —— 这些是「人评」的事，
  规则表只管能被写成判据的缺陷。人评清单见
  [`quality-review-checklist.md`](./quality-review-checklist.md)。
- **文字装不装得下**：那是渲染层的事，由截断规则兜底（SPEC-RND-006），
  不在质量分里重复扣分。
- **语义是否正确**：元素的语义（页眉 / 强调线 / 卡片 …）**已经**从 ID 搬到显式
  字段 `SlideElement.variant`（ADR-018）；规则表只管能被写成判据的缺陷，
  「这个槽位放对了没有」不在扣分项里。
